## Use Comments to Explain Intent

Explain a non-obvious decision, external requirement, or constraint close to the code it affects. A comment should add information beyond a narration of visible operations.

Use actual reasons and evidence. Do not invent performance claims, issue links, or rationales. Update the comment when the decision changes, and retain required attribution and notices.

Reference: [Clean Code, Chapter 4: Comments](https://www.oreilly.com/library/view/clean-code-a/9780136083238/)
