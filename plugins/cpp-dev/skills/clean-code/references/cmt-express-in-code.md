## Express Meaning in Code First

Use clear names, domain concepts, and well-chosen operations to explain what the code does. Extract a named predicate when it clarifies a meaningful condition.

Keep comments for reasons, external constraints, and information that the implementation cannot express clearly. A useful comment and readable code support one another; removing all comments is not the goal.

Reference: [Clean Code, Chapter 4: Comments](https://www.oreilly.com/library/view/clean-code-a/9780136083238/)
