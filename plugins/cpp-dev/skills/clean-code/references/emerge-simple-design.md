## Prefer the Simplest Design That Meets the Contract

Use the simple-design priorities in order: pass the tests, eliminate duplicated knowledge, express intent, and minimize unnecessary elements. Start from actual behavior and requirements rather than an imagined future framework.

Passing an incomplete suite is evidence, not proof of correctness. Preserve behavior while simplifying, and keep structure that serves a real dependency or extension requirement.

Reference: [Clean Code, Chapter 12: Emergence](https://www.oreilly.com/library/view/clean-code-a/9780136083238/)
