## Avoid Redundant Comments

Remove comments that merely repeat an already clear name or operation. Keep useful contract documentation, domain rules, and reasons that readers cannot infer reliably.

For example, a comment should explain why a protocol divides a reading by ten rather than merely state that division occurs. Follow required documentation conventions and preserve legal notices.

Reference: [Clean Code, Chapter 4: Comments](https://www.oreilly.com/library/view/clean-code-a/9780136083238/)
